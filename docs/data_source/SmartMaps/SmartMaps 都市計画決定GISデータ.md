## 概要

国土交通省都市局が全国の市町村と都道府県から集めて整備している、都市計画決定の GIS データを、1 つの PMTiles にまとめたものです。
用途地域、都市計画区域、区域区分 (市街化区域と市街化調整区域)、都市計画道路、公園など 21 のレイヤーが入っていて、[[用途地域]] などの [[都市計画]] の情報を地図に重ねたり、[[土地利用]] の分析に使ったりできます。
範囲は日本全国 (経度 124.07 から 145.04、緯度 24.33 から 45.45) です。

Source Cooperative のリポジトリの題名は「都市計画決定PMTiles」です。
リポジトリには `a.pmtiles` と `README.md` (2,630 バイト) の 2 ファイルがあり、どちらも 2024-05-08 に置かれたままです。
README の題名は「tk」で、レイヤーの一覧、コード表、出典表示と、PMTiles Viewer で表示するリンクが書かれています。

### 元データの年度

SmartMaps の README にもファイルのメタデータにも、元データの年度は書かれていません。
README は元データの仕様書として `https://www.mlit.go.jp/toshi/tosiko/content/001609328.pdf` を挙げていますが、この URL は 2026-10-06 には 404 を返しました。
Web Archive にある 2024-05-31 の元データのページの写しでは、このファイルは「データ定義書.pdf」として載っていて、データ作成年度は令和4年度、更新履歴は令和5年9月15日でした。
ファイルが置かれた 2024-05-08 の時点で公開されていたのもこの版だと考えられるので、令和4年度版から作ったものとして扱います (2024-05-08 時点のページそのものは確かめていません)。

元データのページは 2026-10-06 時点で令和7年度版 (令和8年5月21日公開) に更新されていて、GeoJSON と CityGML の形式も配られています。
このファイルは古い版の写しなので、最新の都市計画を知りたいときは元データのページから取り直してください。
元データ自体も、市町村ごとに時点が違い、掲載されていない市町村やレイヤーがあると、元データのページに書かれています。
各市町村の時点は、元データのページの「公表自治体及び掲載データ一覧.xlsx」で確かめられます。

## 取り出し方

ファイルは 1 つだけで、HTTP Range が効きます。
HEAD は 200 で `Accept-Ranges: bytes` を返し、認証は要りません。
CORS も `Access-Control-Allow-Origin: *` で許可されているので、[[MapLibre GL JS]] から pmtiles プロトコルで直接表示できます。

範囲を絞って手元に取るには、`pmtiles extract` に URL と bbox を渡します。
皇居の東側 (経度 139.75 から 139.78、緯度 35.67 から 35.70) を試すと、18 タイル、約 1.4MB でした。

## 中身

ヘッダとメタデータから読み取れる内容です。

- タイル形式は MVT、タイル圧縮と内部圧縮はどちらも gzip、clustered です。
- タイル数は addressed 56,496、entries 55,261、contents 53,100 です。
- 中心は経度 139.559、緯度 35.326、ズーム 14 に設定されています。
- 生成ツールは `tippecanoe v2.28.0`、生成オプションは `tippecanoe -f -o a.pmtiles` で、最大ズームなどの指定はありません。
- メタデータの `strategies` によると、ズーム 4 から 14 で小さすぎるポリゴンが tippecanoe の既定の処理 (tiny polygon reduction) で簡略化または間引かれています (ズームごとに 4,109 から 14,773 個)。最大ズームの 14 でも行われているので、小さな区域は形が正確でないことがあります。
- メタデータの name と description は `a.pmtiles` で、作成日時はありません。

レイヤーは 21 個で、すべてズーム 0 から 14 にあります。
douro (都市計画道路) だけが LineString で、ほかは Polygon です。
地物数はメタデータの tilestats の値、都道府県数は属性 `Pref` の値の種類数です。

### 属性

すべてのレイヤーに `Citycode` (5 桁の市区町村コード)、`Cityname`、`Pref` があります。
多くのレイヤーには、区分コードの `kubunID` と、元データの名前のままの `名称`、`決定日`、`決定者`、`告示番号` があります。

- youto: `YoutoID` (0 から 13)、`用途地域`、`建ぺい率` (20 から 400)、`容積率` (40 から 1,300)
- douro: `区分` (道路、広場)、`決定区分` (市、県)
- tkbt: `youtoID` (0 から 11)、`用途区分`
- tokei: `tokeiname`
- senbiki と ritteki: `区域区分`

コードの意味は README のコード表にあります。
たとえば `YoutoID` の 1 から 13 は第1種低層住居専用地域から工業専用地域まで、senbiki の `kubunID` の 22 と 23 は市街化区域と市街化調整区域、bouka の 24 と 25 は防火地域と準防火地域です。

### 使うときの注意

- README の「basic schema」には、属性を `code`、`name`、`date`、`status`、`by`、`no`、`city` に統一したと書かれていますが、実際のタイルの属性は上のとおり元の名前のままです。
- 同じ意味の属性でも、レイヤーによって名前と型が違います。`kubunID` は数値のレイヤーと文字列のレイヤーがあり、tokureiyouseki だけ `KubunID` (K が大文字) です。kousoujyukyo は `告示年月日` と `決定権者` を使い、`告示番号` が数値です。
- `決定日` の書き方がそろっていません。`1949-10-04`、`1982/07/07`、`H18.06.07`、`昭和42年12月15日` などが混ざっているので、日付として使うには正規化が要ります。
- README の表記は「特定防火街区整備地区」ですが、データの `Type` は「特定防災街区整備地区」です。
- レイヤーによって入っている都道府県の数が大きく違います (koudoti は 32)。制度上の分布か、元データの未整備かは確かめていません。

## 帰属表示

SmartMaps の README と Source Cooperative の説明欄には、次の出典表示があります。

- 都市計画決定GISデータ（国土交通省）を加工して使用 (https://www.mlit.go.jp/toshi/tosiko/toshi_tosiko_tk_000087.html)

SmartMaps 自身は、加工したこのファイルのライセンスを書いていません。
元データのページには「使用許諾条件」がありますが、ライセンスの名前は書かれておらず、参考情報であること、範囲がおおよそであること、国と自治体が責任を負わないことなどの条件です。
国土交通省ウェブサイトの利用ルール (https://www.mlit.go.jp/link.html) では、特記の無いコンテンツは公共データ利用規約 (第1.0版) (PDL1.0) に準拠した条件で使えます。
別のルールを適用するコンテンツの一覧 (https://www.mlit.go.jp/page/kanbo01_hy_003657.html) に都市計画決定 GIS データは無いので、PDL1.0 によると読めます。
ただし、これは 2026-10-06 時点のルールで、このファイルが作られた 2024-05 時点のルールは確かめていません。

PDL1.0 では、出典の記載と、編集・加工したことの記載が求められます。
このファイルを使うときは、上の出典表示をそのまま引き継ぐのが安全です。

## データ処理コマンド

```bash
# ヘッダとメタデータを表示する
pmtiles show https://data.source.coop/smartmaps/toshik/a.pmtiles

# 範囲を切り出す (例: 皇居の東側)
mkdir -p ./tmp
pmtiles extract https://data.source.coop/smartmaps/toshik/a.pmtiles ./tmp/toshik_tokyo.pmtiles --bbox=139.75,35.67,139.78,35.70
```
